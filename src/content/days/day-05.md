## 1. 需求先于语法

统计结果固定为：

- 总用户数；
- 平均技能数；
- 技能榜：人数降序，同人数技能名升序；
- 技能最多用户：技能数最多，并列取最小 ID；
- 空数据：总数 0、平均 0、空榜、Optional.empty。

先写规则，再写代码。否则一条很长的 Stream 虽然能编译，却没人能确认并列规则和空值语义。

### 1.1 反例：为了 Stream 而 Stream

```java
// 局部反例：多种职责挤在一起，副作用隐藏
users.stream()
        .peek(user -> total[0] += user.skills().size())
        .flatMap(user -> user.skills().stream())
        .forEach(skill -> counts.merge(skill, 1L, Long::sum));
```

问题：

- 用数组绕过 Lambda 的 effectively final 限制；
- peek 修改外部状态；
- 统计总数与技能聚合混在一起；
- 并行执行时有数据竞争；
- 返回值和业务规则不清楚。

今天先保留一份普通循环版作为可读基准，再写等价 Stream 版。

## 2. 函数式接口、Lambda 与方法引用

### 2.1 函数式接口

只有一个抽象方法的接口可作为 Lambda 目标类型。默认、静态、private 方法不计入抽象方法数量。

常见接口：

| 接口 | 抽象形状 | 示例 |
|---|---|---|
| `Predicate<T>` | T → boolean | 过滤 |
| `Function<T,R>` | T → R | 映射 |
| `Consumer<T>` | T → void | 消费 |
| `Supplier<T>` | () → T | 延迟提供 |
| `Comparator<T>` | (T,T) → int | 比较 |
| `UnaryOperator<T>` | T → T | 同类型变换 |

```java
Predicate<User> hasJava = user -> user.skills().contains("Java");
Function<User, String> toName = user -> user.name();
Consumer<String> print = value -> System.out.println(value);
```

Lambda 不是“没有类型的匿名函数”。它的参数和返回规则由目标函数式接口决定。

### 2.2 方法引用

当 Lambda 只是调用现有方法，可用方法引用：

```java
user -> user.name()       // Lambda
User::name                // 等价的方法引用

value -> System.out.println(value)
System.out::println
```

方法引用更短不代表总是更清楚。若需要额外转换、条件或多步逻辑，Lambda 通常更直观。

### 2.3 捕获变量与 effectively final

Lambda 可以读取外部局部变量，但该变量必须是 final 或事实上不再重新赋值。

```java
String expected = "Java";
Predicate<User> predicate = user -> user.skills().contains(expected);
// expected = "Vue"; // 若取消注释，上面的 Lambda 不能编译
```

这是变量引用的限制，不代表引用指向的可变对象自动变得不可变。因此仍要警惕在 Lambda 中修改集合。

**JS/TS 对照**

JS 闭包允许更自由地修改外部变量。Java Lambda 受目标接口和 effectively final 约束，减少部分共享可变状态，但没有自动消除副作用。

## 3. Stream 不是集合

集合保存数据；Stream 描述数据处理流水线。

```java
Stream<User> stream = users.stream();
```

Stream 通常不拥有元素，也不会修改源集合。它把“数据源 + 中间操作 + 终止操作”组合起来。

### 3.1 惰性

```java
var pipeline = users.stream()
        .filter(user -> {
            System.out.println("过滤: " + user.name());
            return !user.skills().isEmpty();
        });
```

此时通常不会打印，因为没有终止操作。加入 `toList()`、`count()`、`collect()` 等终止操作后才真正遍历。

### 3.2 一次消费

```java
Stream<User> stream = users.stream();
long count = stream.count();
// stream.toList(); // 运行时抛 IllegalStateException
```

Stream 一旦被终止操作消费，不能重复使用。需要第二次计算，就从源集合重新创建流。

### 3.3 中间与终止操作

| 类型 | 常见操作 | 返回 |
|---|---|---|
| 中间 | filter、map、flatMap、distinct、sorted、peek | 新 Stream |
| 终止 | count、sum、max、forEach、toList、collect | 值或副作用 |

中间操作通常惰性；终止操作触发遍历。

## 4. 核心操作逐个讲清

### 4.1 filter：保留满足条件的元素

```java
List<User> skilled = users.stream()
        .filter(user -> !user.skills().isEmpty())
        .toList();
```

filter 不改变元素类型，输入 User，输出仍是 User。

### 4.2 map：一对一转换

```java
List<String> names = users.stream()
        .map(User::name)
        .toList();
```

输入一个 User，输出一个 name。

### 4.3 flatMap：一对多后压平

```java
List<String> skills = users.stream()
        .flatMap(user -> user.skills().stream())
        .toList();
```

如果用 map，得到 `Stream<List<String>>`；flatMap 把多个技能流连接成一个 `Stream<String>`。

**面试表达**

map 改变每个元素；flatMap 先把每个元素变成一个流或容器，再压平成单层流。用户到姓名是一对一，用户到技能是一对多。

### 4.4 distinct：按 equals/hashCode 去重

```java
List<String> uniqueSkills = users.stream()
        .flatMap(user -> user.skills().stream())
        .distinct()
        .toList();
```

distinct 依赖 equals/hashCode。自定义对象契约错误，去重就会错误。它通常是有状态操作，需要记录已经见过的元素。

本例 User 构造器已对单个用户技能去重，因此统计人数时不会把同一用户的同一技能重复计数。

### 4.5 sorted：排序

```java
.sorted(Comparator.comparing(User::name))
```

无参 sorted 要求元素实现 Comparable；有参 sorted 使用外部 Comparator。统计规则不应依赖偶然顺序，必须把并列规则写进 Comparator。

## 5. collect、分组与技能榜

Stream 版技能榜：

```java
users.stream()
    .flatMap(user -> user.skills().stream())
    .collect(Collectors.groupingBy(
            Function.identity(),
            Collectors.counting()
    ))
    .entrySet()
    .stream()
    .map(entry -> new SkillCount(entry.getKey(), entry.getValue()))
    .sorted(SKILL_ORDER)
    .toList();
```

逐步解释：

1. flatMap 得到所有技能；
2. groupingBy 以技能名分组；
3. counting 统计每组数量；
4. Map 转 entrySet 再开一条流；
5. entry 映射为明确的 SkillCount；
6. 按业务 Comparator 排序；
7. toList 生成结果。

`Function.identity()` 等价于 `skill -> skill`。

### 5.1 排序规则

```java
Comparator.comparingLong(SkillCount::userCount)
        .reversed()
        .thenComparing(SkillCount::skill,
                String.CASE_INSENSITIVE_ORDER);
```

先人数降序，再名称升序。`reversed()` 放在人数 Comparator 后，避免把后续名称排序也反转。

### 5.2 技能最多用户的并列规则

我们用 max 找“最大”元素。技能数越多越大；技能相同时，ID 越小应被 max 选中。

```java
Comparator.comparingInt(UserSummary::skillCount)
        .thenComparing(UserSummary::id,
                Comparator.reverseOrder());
```

ID 使用反序，是为了让较小 ID 在 Comparator 看来更大，从而被 max 选中。这一处很容易写反，必须用并列测试验证。

## 6. Optional 的正确边界

技能最多用户在空列表中不存在，所以结果使用 `Optional<UserSummary>`。

Optional 适合作为“一个结果可能缺失”的返回值。它通常不适合作为实体字段、方法参数或集合元素的默认替代，因为会增加模型和序列化复杂度。

### 6.1 常用读取方式

```java
optional.map(UserSummary::name)
        .ifPresent(System.out::println);

UserSummary value = optional.orElse(defaultValue);
UserSummary lazy = optional.orElseGet(this::createDefault);
UserSummary required = optional.orElseThrow();
```

### 6.2 orElse 与 orElseGet

`orElse(expensive())` 会先计算参数，即使 Optional 有值；`orElseGet(() -> expensive())` 只在为空时调用 Supplier。

```java
String value = optional.orElse(createExpensiveDefault());
String lazy = optional.orElseGet(this::createExpensiveDefault);
```

若默认值是常量，orElse 很清楚；若创建昂贵或有副作用，优先 orElseGet。

### 6.3 不要滥用 get

直接 `optional.get()` 在空时抛 NoSuchElementException，而且没表达空值策略。优先 map、ifPresent、orElse、orElseGet 或 orElseThrow。

## 7. 循环版与 Stream 版逐段对照

| 任务 | 循环版 | Stream 版 |
|---|---|---|
| 总技能数 | for 中累加 | mapToLong + sum |
| 技能计数 | Map.merge | groupingBy + counting |
| 榜单转换 | 遍历 entrySet | map |
| 榜单排序 | List.sort | sorted |
| 最多技能用户 | 条件比较 | map + max |
| 空数据 | 提前返回 | 同样提前返回 |

保留循环版有三个价值：

1. 初学者可以逐句断点；
2. 它是 Stream 重构的行为基准；
3. 某些带复杂状态和提前退出的算法，循环更清楚。

Stream 不是“高级写法”，循环也不是“落后写法”。选择标准是语义、可读性、正确性和性能证据。

## 8. 副作用和并行流风险

理想的 map、filter 函数应尽量纯：同样输入得到同样输出，不修改外部状态。

`peek` 主要用于调试观察，不应用来承载关键业务副作用。

本课明确不使用 parallelStream，原因包括：

- 数据量小，并行开销可能更大；
- 共享可变 Map 或计数器会有数据竞争；
- 顺序、副作用和线程池行为更难解释；
- 性能必须用基准测量，不能凭“并行”二字判断。

如果未来考虑并行，先确保操作无副作用、Collector 支持并发语义，并测量真实数据。

## 11. 常见错误排查

| 现象 | 原因 | 修复 |
|---|---|---|
| Stream 没执行 | 没有终止操作 | 添加 toList/count/collect 等 |
| `stream has already been operated upon` | 重复消费 | 从集合重新 stream |
| 并列用户选了大 ID | Comparator 方向错 | 用测试验证 max 规则 |
| 榜单同人数顺序漂移 | 缺次级排序 | thenComparing 名称 |
| 同一用户技能重复计数 | 输入未去重 | User 边界去重或流 distinct |
| 空列表 max 报错 | 直接 get | 保留 Optional.empty |
| orElse 仍执行昂贵方法 | 参数急切求值 | 使用 orElseGet |
| 循环和 Stream 结果不同 | 规则实现不一致 | 共享 Comparator 和值对象 |
| 修改外部 Map 出错 | 流中副作用 | 使用 Collector 或回到循环 |
| parallel 后偶发错误 | 共享可变状态 | 不盲目 parallelStream |

```java
import java.util.LinkedHashSet;

public record User(Long id, String name, List<String> skills) {
    public User {

        LinkedHashSet<String> normalized = new LinkedHashSet<>();
        for (String skill : skills) {
            if (skill != null && !skill.isBlank()) normalized.add(skill.trim());
        }
        skills = List.copyOf(normalized);
    }
}
```

### src/com/example/day5/UserStatisticsService.java

<!-- file: src/com/example/day5/UserStatisticsService.java -->

```java
package com.example.day5;

import java.util.ArrayList;
import java.util.Comparator;
import java.util.HashMap;
import java.util.List;
import java.util.Map;
import java.util.Optional;
import java.util.function.Function;
import java.util.stream.Collectors;

public final class UserStatisticsService {
    private static final Comparator<SkillCount> SKILL_ORDER =
            Comparator.comparingLong(SkillCount::userCount)
                    .reversed()
                    .thenComparing(SkillCount::skill, String.CASE_INSENSITIVE_ORDER);

    private static final Comparator<UserSummary> MOST_SKILLED_ORDER =
            Comparator.comparingInt(UserSummary::skillCount)
                    .thenComparing(UserSummary::id, Comparator.reverseOrder());

    public UserStatistics calculateWithLoops(List<User> users) {
        if (users.isEmpty()) return UserStatistics.empty();

        Map<String, Long> counts = new HashMap<>();
        long totalSkills = 0;
        UserSummary mostSkilled = null;

        for (User user : users) {
            int skillCount = user.skills().size();
            totalSkills += skillCount;
            UserSummary summary = new UserSummary(user.id(), user.name(), skillCount);
            if (mostSkilled == null || MOST_SKILLED_ORDER.compare(summary, mostSkilled) > 0) {
                mostSkilled = summary;
            }
            for (String skill : user.skills()) {
                counts.merge(skill, 1L, Long::sum);
            }
        }

        List<SkillCount> ranking = new ArrayList<>();
        for (Map.Entry<String, Long> entry : counts.entrySet()) {
            ranking.add(new SkillCount(entry.getKey(), entry.getValue()));
        }
        ranking.sort(SKILL_ORDER);

        return new UserStatistics(
                users.size(),
                (double) totalSkills / users.size(),
                ranking,
                Optional.of(mostSkilled)
        );
    }

    public UserStatistics calculateWithStreams(List<User> users) {
        if (users.isEmpty()) return UserStatistics.empty();

        long totalSkills = users.stream()
                .mapToLong(user -> user.skills().size())
                .sum();

        List<SkillCount> ranking = users.stream()
                .flatMap(user -> user.skills().stream())
                .collect(Collectors.groupingBy(Function.identity(), Collectors.counting()))
                .entrySet()
                .stream()
                .map(entry -> new SkillCount(entry.getKey(), entry.getValue()))
                .sorted(SKILL_ORDER)
                .toList();

        Optional<UserSummary> mostSkilled = users.stream()
                .map(user -> new UserSummary(user.id(), user.name(), user.skills().size()))
                .max(MOST_SKILLED_ORDER);

        return new UserStatistics(
                users.size(),
                (double) totalSkills / users.size(),
                ranking,
                mostSkilled
        );
    }
}
```

### src/com/example/day5/App.java

```java
package com.example.day5;

import java.util.List;

public final class App {
    public static void main(String[] args) {
        List<User> users = List.of(
                new User(1L, "Alice", List.of("Java", "TypeScript", "SQL")),
                new User(2L, "Bob", List.of("Java", "Vue", "SQL")),
                new User(3L, "Cara", List.of("Python")),
                new User(4L, "David", List.of("Java", "Spring")),
                new User(5L, "Eve", List.of())
        );

        UserStatisticsService service = new UserStatisticsService();
        UserStatistics loops = service.calculateWithLoops(users);
        UserStatistics streams = service.calculateWithStreams(users);

        if (!loops.equals(streams)) {
            throw new IllegalStateException("循环版和 Stream 版结果不一致");
        }

        System.out.println("总用户数: " + loops.totalUsers());
        System.out.printf("平均技能数: %.2f%n", loops.averageSkills());
        System.out.println("技能榜: " + loops.skillRanking());
        System.out.println("技能最多用户: " + loops.mostSkilledUser().orElseThrow());
        System.out.println("两种实现一致: " + loops.equals(streams));

        UserStatistics empty = service.calculateWithStreams(List.of());
        System.out.println("空数据: " + empty);
    }
}
```
